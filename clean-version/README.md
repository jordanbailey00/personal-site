# Jordan Bailey — clean version

A small, static portfolio based on the supplied Aeree Cho website oracle. It follows the reference's white canvas, narrow column, circular profile image, quiet section dividers, and image/text project rows. No runtime framework, third-party services, API keys, or build dependencies are required. A shared theme picker offers Auto, Light, Rust, Coal, Navy, Ayu, Supernova, and Novasuper on every page. Supernova is the default; Auto follows the device appearance; an explicit selection persists across pages, tabs, and visits. Old dark-mode preferences map to Coal. Rust is a warm ivory reading palette (`#f2e7d5`) with soft brown text and muted copper accents; Light retains its white background.

## Develop

```sh
npm run dev
```

Open http://127.0.0.1:4173. The development server (`scripts/dev.mjs`, no dependencies) serves `dist/` and the local inbox for "message me"; its reply tool is at http://127.0.0.1:4173/inbox/. Re-run `npm run build` after editing. `npm run check` verifies the generated pages, internal links, theme persistence/device changes/storage fallbacks, retired style preference migration, keyboard menu dismissal, multi-article listing behavior, current-section tracking, and both star themes’ animation lifecycle.

Profile and project metadata live in `content/site.mjs`. The four project summaries in `content/*.html` give a short, plain-language introduction and a few outcomes. Keep these around 100 words, with occasional light humor; long explanations belong in Writing, and implementation details belong on GitHub. The original long case studies remain in the retired site and Git history. `scripts/import-case-studies.cjs` is a legacy importer and would overwrite the concise summaries. Layout and page generation live in `scripts/build.mjs`; styling lives in `assets/style.css`.

To add or migrate an essay:

1. Copy `templates/article.html` to `content/writing/<slug>.html`. Replace the sample content with the essay body; the layout supplies its title, author, date, and navigation.
2. Add an entry to `content/writing/posts.mjs` with `slug`, `title`, `subtitle`, an ISO `date`, `file`, and `status: 'draft'`. Drafts are omitted from the output entirely. Manifest order is the index and previous/next order.
3. Use `<h2 id="section-name">…</h2>` and `<h3 id="subsection-name">…</h3>` for automatic section navigation. IDs must be unique, lowercase, and hyphenated. Put images in `public/writing/<slug>/` and refer to them with absolute `/writing/<slug>/…` URLs.
4. Change the status to `published` when the essay is ready, then build and check. The homepage, hub, chapter links, reading time, and sitemap update automatically.

Add a `thumbnail` object to each essay's metadata with `src`, descriptive `alt` text, and the source image's pixel `width` and `height`. For example: `thumbnail: { src: '/writing/my-essay/thumbnail.jpg', alt: 'A description of the image', width: 640, height: 640 }`. Store the image in `public/writing/<slug>/`. The writing hub and homepage show the same thumbnail beside the title, summary, and date; the entire entry links to the article. Images fit inside a square without cropping and shrink on mobile. Entries without thumbnail metadata remain text-only.

The template demonstrates `.with-margin` + `.margin-note` (responsive side footnotes with reference and return links), `.concept-box`, `.example-box`, `.notebook` with copyable code and static output, `.reading-details`, `.article-figure`, `.wide-figure`, `.table-scroll`, and `.reference-list`. Code/output is presentational; it does not execute readers' code. Figures use the reading column’s width and may contain supplied images, video, or accessible iframe embeds. Equations can use semantic MathML or authored HTML; no remote rendering service is required. All writing content remains readable without JavaScript; navigation controls, reading progress, and copying progressively enhance it.

Use `<p class="drop-cap">…</p>` for a section's opening paragraph. The decorative Goudy initial retains its size, weight, and spacing alongside Ubuntu Sans body text. Its rule and font import live in `assets/writing.css`. The text remains one paragraph for selection and screen readers.

The reading implementation is in `scripts/writing.mjs`, `assets/writing.css`, and `assets/writing.js`. The shared appearance controls are in `scripts/appearance.mjs` and `assets/theme.js`. All palettes and shared typography live in `assets/style.css`. The original site and favicon are preserved.


## Typography

The site explicitly loads bundled **Ubuntu Sans 1.006** for body text, subtitles, section headings, entry titles, and the CV. Akzidenz Grotesk BQ Bold is used only for Jordan's name on the homepage and CV. The user-supplied font-inspector screenshots are the typography reference; relying on `system-ui` or OS fallback stacks does not reproduce their Ubuntu Sans appearance on other systems.

The homepage uses a 16.2px root: the name is 2.5rem / 1 line height / weight 600 / −0.08rem tracking; the subtitle is 1.17rem / 1.2 / 400; body copy is 1rem / 1.6 / 400; section headings are 1.4rem / 1.6 / 500; entry titles are 1rem / 1.6 / 600; date labels are 0.8rem / 1.3 / 400. Project descriptions use 0.95rem / 1.3 / 400. Homepage section underlines and 3rem gaps keep sections distinct. At the reference's 700px breakpoint, the homepage name becomes 2.2rem and its subtitle 0.85rem.

The CV retains its separate scale: 2.25rem / 1.25 / 600 for the Akzidenz name, 2rem / 1.5 / 400 for section headings, and 1rem / 1.5 body copy. All CV text except the name, including the subtitle, uses Ubuntu Sans. Color themes and existing content layouts remain available.
The paintbrush control selects among eight color themes; there is one shared typography throughout the site. The retired **Aa** style picker and Fantasy stylesheet have been removed. Existing `jordan-bailey-style` preferences are cleared on load. The `jordan-bailey-theme` preference is applied before CSS loads and synchronized across tabs. Storage failures still permit selections for the current page.

The homepage description uses uniform regular-weight text. CV highlights share rounded shapes and padding across themes. Dark CV themes pair muted green, blue, and rose backgrounds with light accent text. Generated stylesheet and behavior-script URLs include content hashes to prevent stale assets after deployments. CV navigation also includes a version derived from the shared palette, CV stylesheet, and theme script, so an older cached CV document does not retain a previous palette when opened from the updated site.

To add a footnote, use the `.with-margin` wrapper from `templates/article.html`, containing a text `<div>` and an `<aside class="margin-note">`. Put it around the paragraph that contains the reference, give each reference/note pair unique IDs and reciprocal links, and keep notes concise. The shared grid reserves enough vertical space for long notes to avoid collisions. No scripting or duplicate mobile note content is required.

## Supernova and Novasuper

Supernova brings back the original star field from `space-version/components/starfield/Starfield.tsx`, with its 5,000 white circular particles in a spherical shell (radii 20–80), camera at z=5 and 60° field of view, volume offset z=−60, fog at 25–120, 0.15 point size, 0.7 opacity, and rotation rates x=0.005, y=0.015, z=0.002 radians/second. The shared theme picker selects either star theme on every page. Layout, typography, and the favicon remain unchanged.

Novasuper is Supernova’s exact color inverse: a white background, dark stars, and dark text. Its palette variables invert Supernova’s colors, and a CSS filter inverts only the star-field canvas. Photos, book covers, and other media retain their original colors. Switching between the two star themes reuses the same renderer and star positions.

`assets/starfield.js` draws the star field with a few lines of WebGL (one shader, one draw call) rather than a 3D library: it replaced a 725 KB Three.js build whose download chain and roughly half a second of setup delayed the stars on first visits, more so in private windows, which keep no compiled-code or shader caches. Pages preload the 7 KB renderer, and `assets/supernova.js` starts it only when either star theme is visible and selected. It sets up WebGL just after the page first paints, sizes its canvas before creating the context, compiles its shaders in the background where the browser supports it, and fades the stars in once they can draw, so it never delays the page. To stay light on modest machines it draws without multisampling, redraws at most 30 times a second (the shell turns slowly), and caps its drawing buffer at about two million pixels however dense the display. The effect pauses in hidden tabs, disposes its graphics resources when leaving both star themes, and shows a still star field for reduced-motion preferences. WebGL failures leave the selected black or white palette readable. Printing hides the canvas and uses the existing light print palette.

## Lunar lander

The homepage has a small lunar lander parked on a pad in the window's bottom-right corner. A handwritten "play here" note with a hand-drawn arrow points visitors to it: once its font has loaded, the words write themselves in and the arrow draws toward the lander within about a second. It steps aside while the lander is hovered, focused, or flying, stays away for the rest of the visit once the visitor has flown, and returns on every page load. It shows only where the window is at least 1240px wide, so it sits in the margin beside the text column. Visitors click the lander (or focus it and press Enter) to fly it and start a one-minute round. W, A, S, and D fire the main engine and reaction-control jets; the flight keys follow physical key positions, so other keyboard layouts fly the same way. The mouse aims (a crosshair replaces the pointer), either mouse button fires, and the scroll wheel changes guns, one per notch. During a round, clicks fire instead of following links, selecting text, or landing. M turns the sound on or off, and this browser remembers the choice. Esc (or Enter on the lander) or tabbing elsewhere lands it early; the autopilot then flies it back to its pad. Until a visitor chooses to fly, every key, click, and scroll works on the page as usual: the mouse listeners exist only during a flight, Space and the arrow keys never fire, and mouse pilots get their keys back as soon as they land. Flying past the top of the window scrolls the page up with the lander until the page itself ends, and holding S while diving past the bottom scrolls it back down; plain falling still lands on the window's floor. While flying, it can land on top of images (only the crown of the round portrait), on the main section dividers, and on the gun bar. Platforms are one-way, so it flies up through them from below, and holding S drops through them; a perched lander rides its platform as the page scrolls and falls when the platform leaves the window or the lander slides off an edge. The autopilot ignores platforms on its way home. Shots spark against images, the social icons, and the name without changing the page.

Each round lasts 60 seconds. Space targets warp in or cross the window and can be shot for points: asteroids (10, breaking into two 15-point rocks), satellites (25), saucers (50), and the occasional comet (100). Four targets appear at first, rising to eight as the round goes on. The score, the visitor's best score (remembered in this browser), and the time left appear in the window's top-right corner; the last ten seconds are highlighted and the last five tick. When time runs out or the lander lands, the targets leave and the result (with any new best) replaces the gun bar for a few seconds, and screen readers hear it.

There are five guns, shown in the gun bar at the bottom center with the current one raised. The Blaster fires fast single bolts; Scatter fires a seven-shot fan with a short range and a heavy kick; Rapid fires a stream of tracers; the Laser fires a wide, piercing beam that burns through everything in its path, drains the energy meter under its slot, and overheats when empty until it recharges; Missiles leave from alternate sides, lock onto the target nearest the crosshair, and burst, destroying every target within the blast. Every gun has recoil, a muzzle flash, and its own sound, and heavy guns and explosions shake the game layer (never the page). Destroyed targets burst into pieces in their own colors. Sounds are synthesized sci-fi effects made with the Web Audio API, so there are no audio files: frequency-modulated zaps and bells, resonant filter sweeps (Scatter's plasma "vwomp"), a crackling rocket motor that flies off with each missile, a deep, muffled boom when it bursts, filtered noise, and a dark echo, each panned toward where it happens. Asteroids and rocks break with a deep fracture (a groan, a crack, a heavy boom, and crumbling), satellites with an electrical failure (a pop, sparks, and power dying), and at most three break sounds start in any brief instant, however many targets a missile or the laser destroys. Nothing plays before a visitor starts flying.

The lander, targets, and effects follow the active palette: theme ink and paper, gold foil from the badge color, and the focus accent for the beacon, shots, beam, crosshair, and points. It appears only on devices with a hovering, fine pointer and windows at least 900px wide, where it can be flown and stays beside the text column. Reduced-motion preferences park it immediately instead of flying it home and turn off the shaking. The animation runs only while something moves or a round is on; a parked lander uses no animation frames and releases its effects canvas. To stay smooth on modest machines, the effects canvas draws near device resolution only up to about two million pixels, displays above 90 Hz update every other frame, shots test page elements against rectangles measured once a frame instead of hit-testing the page, small particles are drawn as squares with no paths to build, glows are stamped from a sprite painted once per palette, and the laser's meter changes without reflowing the page.

`assets/lander.js` contains the DOM-free flight model and the page controls; `assets/space-targets.js` contains the targets, scoring, the round timer, and their drawing; `assets/guns.js` contains the guns, aiming, shots, recoil, and the laser's energy; `assets/lander-sound.js` synthesizes the sounds; `assets/lander.css` styles the lander, pad, hint, score, gun bar, and results. Only the homepage loads them. The build versions these modules where `lander.js` imports them, so a deployment never pairs a fresh script with a cached module. `scripts/lander.test.mjs`, `scripts/space-targets.test.mjs`, and `scripts/guns.test.mjs` cover flight, the keyboard and mouse hand-off, idle behavior, rounds, spawning, hits, scoring, and each gun.

## message me

The message page, `/message/`, lets visitors type a note or draw a picture (or both) and send it, with an optional name. The homepage links to it from a "message me" pill under the social links and from "Get in touch". Nothing visitors send appears on the site by itself: Jordan answers messages in the reply tool and chooses which to publish, and only those, with their answers, ship with the next deploy.

- **The page.** It is made from the homepage's own pieces. A handwritten "write or draw here" note, in the same hand and with the same write-in animation as the lander's "play here" note, points at the writing sheet: from beside it on windows at least 1240 pixels wide, from above it otherwise. After a message is sent, the note writes "got it, thanks!". The sheet lets the stars show faintly through. Type and Draw are a switch whose highlight slides to the chosen side (Type's cursor blinks; Draw's pencil scribbles a line), and Send carries a rocket that lights the lander's flame colors on hover and launches with each message.
- **Sending.** `assets/messages.js` runs the form: the Type/Draw switch, a 600 × 240 drawing pad (mouse, finger, or pen) with six pen colors (ink, which follows the theme, plus red, orange, green, blue, and purple, set in `assets/messages.css`), an eraser, and Clear, a character count, and a status line. Drawings are kept as strokes of whole-number points with an optional pen color for each, so a published drawing is a crisp SVG, cropped to what was drawn but kept at the pad's scale. The eraser cuts away just the parts of strokes it touches, splitting them where it crosses, so drawings stay plain strokes. The same module holds the message rules (up to 1,000 characters, a 40-character name, 200 strokes and 5,000 points), shared by the form, the inbox, and the build. A hidden field and the time spent on the page let the inbox quietly drop bot submissions; the form pauses briefly after sending.
- **Inbox.** Locally, the form sends to the development server, which saves each message as a JSON file in `inbox/` (ignored by Git, never deployed). On the live site it sends to `messageEndpoint` in `content/site.mjs`; until an inbox service is set there, the form says messages open soon.
- **Replying.** The reply tool at http://127.0.0.1:4173/inbox/ (served only by the development server) lists new and published messages. Publish with answer moves a message and the answer into `content/messages.json` and rebuilds the local site; Save answer edits a published answer; Unpublish returns a message to the inbox; Archive moves it to `inbox/archived/`. Review the message page locally, then commit and deploy when ready.
- **Showing.** `scripts/messages.mjs` validates `content/messages.json` (newest first; each entry needs an answer) and renders the page: the form, then the ten newest answers, folding older ones under "Show more". Each message appears as it was written or drawn, with Jordan's answer below in the gold of the lander's foil, marked with the lander (`SPRITE`, exported by `assets/lander.js`). Visitor text is always escaped. `assets/messages.css` styles the page; the homepage pill's styles are in `assets/style.css`. `scripts/messages.test.mjs` covers the rules, pen colors, the eraser, the page, drawing crops, and the inbox.
